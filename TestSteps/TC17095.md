# TC17095 - GroupKPIs_WhenUserHasNoKPIAccess_ShouldMakeEnableDisableAndEditUnavailable

Release ORION 2025.2000.1 - RT-25957 (Group KPIs). Spec: tests/RT25957.spec.ts.

Categories: Regression, KPI, GroupKPIs, Administration, Permissions, Negative

Setup (Setups/TC17095.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name). The user without KPI access is not created by the setup (the Worker Portal DLL has no user/role methods): it is a user set up once by hand and given in .env as ORION_NOKPI_USERNAME / ORION_NOKPI_PASSWORD (Base64); the test is skipped when they are not set.

Steps in the test:

1. Log in as the main automation user, open the group (Administration > Groups) and its Group KPIs tab.
2. Enable Claims Pending with a complete configuration (More, value 4, Current Month, Ticker); leave Claims Worked disabled.
3. In a second browser session log in as the user without KPI access, open the same group and its Group KPIs tab.
4. Verify the KPIs are listed.
5. Verify Disable is unavailable on the enabled KPI (not shown or disabled).
6. Verify Enable is unavailable on the disabled KPI (Claims Worked).
7. Select the enabled KPI and verify no Edit option is offered and the Benchmark, Benchmark value and Period measured cannot be changed.

Notes:
- Test case wording follows the FRD; in the build Claim KPIs / CS KPIs are the Claims Processing KPIs / Customer Service KPIs headings, Period measured is Time Period, Style is Display Type (Three Bar Graph = Bar) and every change in the KPI editor is saved as it is made (no Save button).
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
