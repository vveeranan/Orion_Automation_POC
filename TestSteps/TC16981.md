# TC16981 - TaskKPI_WhenMeasurementPeriodIsMissing_ShouldApplyApprovedVisibility

Release ORION 2025.2000.1 - RT:27053 (KPI ribbon and KPI configuration).

Categories: Regression, KPI, Configuration, Ribbon, CustomerService, Tickets

Setup (Setups/TC16981.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name) and 3 tickets (Tickets.CreateTicket) as data for the Customer Service KPIs. The KPI configuration is stored per group, so every test works on its own group and the logged in user is assigned to it by the test.

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. On Group Assignments click the logged in user in the Users list to assign them to the group (a clean-up step takes them out again after the test).
4. Open the Group KPIs tab.
5. Enable Tickets Created and set only the Benchmark (More), its value and the Display Type (Ticker) - no Time Period.
6. Verify the KPI is flagged "not configured!".
7. Go to the Tickets page and verify no tile is shown.
8. Go back, select the KPI, set the Time Period to Current Month and verify the "not configured!" flag goes; on Tickets verify the tile now appears.

Notes:
- The test cases are named "TaskKPI"; in the build under test the KPI feature has Claims Processing KPIs (Claims Queue ribbon) and Customer Service KPIs (Tickets ribbon), and My Tasks has no KPI ribbon. "Task" KPIs are therefore the Customer Service KPIs and "My Task" is the Tickets page.
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
