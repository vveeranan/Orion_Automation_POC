# TC17091 - GroupKPIs_WhenBenchmarkValueEditedFromDetails_ShouldShowNewValueInDetailsAndRibbon

Release ORION 2025.2000.1 - RT-25957 (Group KPIs). Spec: tests/RT25957.spec.ts.

Categories: Regression, KPI, GroupKPIs, Administration, Claims, Details, Ribbon

Setup (Setups/TC17091.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name); test data: Benchmark value 4 and the new value 8.

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. On Group Assignments click the logged in user in the Users list to assign them to the group (an afterEach clean-up takes them out again).
4. Open the Group KPIs tab.
5. Enable Claims Pending and set Benchmark More, the Benchmark value, Period measured (Time Period) and Style (Display Type); each change is saved as it is made. (More, value 4, Current Month, Ticker)
6. Select the enabled KPI (its details) and change the Benchmark value to 8; it is saved as it is made.
7. Verify the details show 8, also after reloading the group and selecting the KPI again.
8. Go to My Claims Queue, open the KPI tile and verify the Benchmark in its information dialog ends with 8.

Notes:
- In the build the KPI details and the edit panel are the same panel, so "Edit ... and Save" is a change of the field that is saved straight away.
- Test case wording follows the FRD; in the build Claim KPIs / CS KPIs are the Claims Processing KPIs / Customer Service KPIs headings, Period measured is Time Period, Style is Display Type (Three Bar Graph = Bar) and every change in the KPI editor is saved as it is made (no Save button).
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
