# TC16989 - TaskKPI_WhenExistingKPIUsesBenchmark_ShouldValidateBenchmarkValue

Release ORION 2025.2000.1 - RT:27053 (KPI ribbon and KPI configuration).

Categories: Regression, KPI, Configuration, Existing, Claims, Validation

Setup (Setups/TC16989.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name). The KPI configuration is stored per group, so every test works on its own group and the logged in user is assigned to it by the test.

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. On Group Assignments click the logged in user in the Users list to assign them to the group (a clean-up step takes them out again after the test).
4. Open the Group KPIs tab.
5. Enable Claims Pending and select it.
6. With no Benchmark selected verify the Benchmark Value field is disabled (it only matters once a Benchmark is chosen).
7. Select Benchmark More: verify the value field is enabled and labelled "Higher than".
8. Enter the benchmark value, set Time Period Current Day and Display Type Ticker; verify the "not configured!" flag goes.
9. Go to My Claims Queue, open the tile and verify Benchmark "> <value>".
10. Go back, select Benchmark Less: verify the label is "Lower than" and the value is kept; on My Claims Queue verify the dialog shows "<= <value>".

Notes:
- The test cases are named "TaskKPI"; in the build under test the KPI feature has Claims Processing KPIs (Claims Queue ribbon) and Customer Service KPIs (Tickets ribbon), and My Tasks has no KPI ribbon. "Task" KPIs are therefore the Customer Service KPIs and "My Task" is the Tickets page.
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
