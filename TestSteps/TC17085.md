# TC17085 - GroupKPIs_WhenBenchmarkValueEmpty_ShouldNotConfigureKPI

Release ORION 2025.2000.1 - RT-25957 (Group KPIs). Spec: tests/RT25957.spec.ts.

Categories: Regression, KPI, GroupKPIs, Administration, Claims, Negative

Setup (Setups/TC17085.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name).

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. On Group Assignments click the logged in user in the Users list to assign them to the group (an afterEach clean-up takes them out again).
4. Open the Group KPIs tab.
5. Enable Claims Pending and set Benchmark More, Period measured Current Month and Style Ticker, but leave the Benchmark value empty.
6. Verify the Benchmark value is still empty and (soft) the KPI is flagged "not configured!".
7. Go to My Claims Queue and verify the ribbon shows no tile for the KPI.
8. Go back to the group, select the KPI and verify the Benchmark value is still empty (nothing was saved for it).

Notes:
- The build has no Save button (changes are saved as they are made) and enabling saves at once, so "save refused and KPI stays disabled" is verified as: the KPI is not a complete configuration, is not offered to users in the ribbon and the empty value is kept.
- Test case wording follows the FRD; in the build Claim KPIs / CS KPIs are the Claims Processing KPIs / Customer Service KPIs headings, Period measured is Time Period, Style is Display Type (Three Bar Graph = Bar) and every change in the KPI editor is saved as it is made (no Save button).
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
