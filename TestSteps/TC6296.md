# TC6296 - QC Orion - Create a Queued Claim Task and View in My Tasks

Categories: Smoke, Queue, Claims, Task, Administration

Setup (Setups/TC6296.cs): creates the whole dependency chain in QC (client, group, benefit plan and contract, vendor, member, provider, fee schedule, payment contract) and a professional claim, which is adjudicated (status Approved). The queue is the existing ALL CLAIMS queue.

Steps 1-5 are done by the shared function `reloadQueues` in utils/queues.ts (also available to other spec files):

1. Log in to Orion and go to Administration > Queues.
2. Select the existing ALL CLAIMS queue (nothing is created) and verify the page is for that queue.
3. Click Assignments and assign the queue to the logged in user, unless the user is already assigned (clicking an assigned user would remove the assignment), then close the panel.
4. Click Criteria. In the Criteria popup click the Claim Form Type header, click Add, open the Value drop down, select Dental (it saves as soon as it is selected), then click Remove so the queue is left as it was, and close the popup.
5. Click Reload and wait for the queue to finish reloading. The claim from the setup is now queued.

Steps in the test:

6. Go to Claim Inventory Management > My Claims Queue and wait for the grid to load.
7. Search for the claim created by the setup and click it. This makes the claim active for the user and opens a panel on the left-hand side.
8. In that panel click the Tasks tab, click Add Task, enter the task title (the task is created as soon as the title is entered) and the description, and assign the task to the logged in user (Assigned To).
9. Go to My Tasks.
10. Verify the task is displayed (the page shows "0 Tasks" until its data arrives, so it is reloaded until the task is listed).

Notes:
- The QC database is on QC Core 47.0.18 (2025.2000.0), so the project uses the matching QC DLLs from the QC_Orion_Playwright_UI References folder instead of 2025.2000.1, which reads a column the database does not have (benefit_contract.is_payment_this_contract_only). That set has no ClaimsCommon.GetAllGender / GetAllMaritalStatus / GetAllMemberIdType, so the setups use the literal values Male, Single and PID.
- Each click on Add in the Criteria popup saves an empty criterion immediately and the new row takes several seconds to appear, so it must be clicked once and waited for.
