# TC16970 - TaskKPI_WhenConfigured_ShouldDisplayInMyTask

Release ORION 2025.2000.1 - RT:27053 (KPI ribbon and KPI configuration).

Categories: Regression, KPI, Ribbon, CustomerService, Tickets

Setup (Setups/TC16970.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name) and 3 tickets (Tickets.CreateTicket) as data for the Customer Service KPIs. The KPI configuration is stored per group, so every test works on its own group and the logged in user is assigned to it by the test.

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. On Group Assignments click the logged in user in the Users list to assign them to the group (a clean-up step takes them out again after the test).
4. Open the Group KPIs tab.
5. Enable Tickets Created if needed, select it and set Benchmark More, the benchmark value, Time Period Current Month, Display Type Ticker (each change is saved straight away).
6. Go to the Tickets page (the page that carries the Customer Service KPI ribbon; "My Task" in the test case name).
7. Verify exactly one ticker tile is shown: short name CS-CREA, the group name in brackets and the values "user / group average / benchmark" with the configured benchmark value.
8. Verify the Add Ticket button and the tickets grid are still there.

Notes:
- The test cases are named "TaskKPI"; in the build under test the KPI feature has Claims Processing KPIs (Claims Queue ribbon) and Customer Service KPIs (Tickets ribbon), and My Tasks has no KPI ribbon. "Task" KPIs are therefore the Customer Service KPIs and "My Task" is the Tickets page.
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
