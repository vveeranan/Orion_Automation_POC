# TC16968 - TaskKPI_WhenUserEnablesTaskKPI_ShouldSaveConfiguration

Release ORION 2025.2000.1 - RT:27053 (KPI ribbon and KPI configuration).

Categories: Regression, KPI, Configuration, Group, CustomerService, Administration

Setup (Setups/TC16968.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name). The KPI configuration is stored per group, so every test works on its own group and the logged in user is assigned to it by the test.

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. Open the Group KPIs tab.
4. Click Enable on Tickets Created and wait for the configuration save (POST /api/groups/{id}/configuration, KPI_DISPLAY_TICKETS_CREATED = enabled); the button changes to Disable.
5. Verify the KPI is flagged "not configured!" (no Benchmark or Time Period yet).
6. Reload the page, open Group KPIs again and verify the KPI is still enabled and still flagged, and a different KPI (Tickets Resolved) is still not enabled.

Notes:
- The test cases are named "TaskKPI"; in the build under test the KPI feature has Claims Processing KPIs (Claims Queue ribbon) and Customer Service KPIs (Tickets ribbon), and My Tasks has no KPI ribbon. "Task" KPIs are therefore the Customer Service KPIs and "My Task" is the Tickets page.
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
