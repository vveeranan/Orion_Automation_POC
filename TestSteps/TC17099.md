# TC17099 - GroupKPIs_WhenAnotherEnabledKPISelected_ShouldShowItsOwnConfiguration

Release ORION 2025.2000.1 - RT-25957 (Group KPIs). Spec: tests/RT25957.spec.ts.

Categories: Regression, KPI, GroupKPIs, Administration, Claims, Details

Setup (Setups/TC17099.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name); test data: the two KPIs (Claims Pending, Claims Worked) and their Benchmark values (3, 9).

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. Open the Group KPIs tab.
4. Enable Claims Pending (More, 3, Current Day, Ticker) and Claims Worked (Less, 9, Current Month, Three Bar Graph).
5. Select Claims Pending and verify the details show More, 3 and Current Day.
6. Select Claims Worked and verify the details change to Claims Worked: Less, 9 and Current Month, with no Claims Pending heading left over.
7. Select Claims Pending again and verify its own configuration is shown again.

Notes:
- Test case wording follows the FRD; in the build Claim KPIs / CS KPIs are the Claims Processing KPIs / Customer Service KPIs headings, Period measured is Time Period, Style is Display Type (Three Bar Graph = Bar) and every change in the KPI editor is saved as it is made (no Save button).
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
