# TC16979 - TaskKPI_WhenTaskDataReachesBoundary_ShouldApplyApprovedCalculation

Release ORION 2025.2000.1 - RT:27053 (KPI ribbon and KPI configuration).

Categories: Regression, KPI, Ribbon, Calculation, Boundary, CustomerService, Tickets

Setup (Setups/TC16979.cs): creates the group the test configures its KPIs on (Orion Worker Portal DLL: Groups.CreateGroup, read-or-create by name) and 3 tickets (Tickets.CreateTicket) as data for the Customer Service KPIs. The KPI configuration is stored per group, so every test works on its own group and the logged in user is assigned to it by the test.

Steps in the test:

1. Log in to Orion.
2. Go to Administration > Groups, search for the group created by the setup and open it.
3. On Group Assignments click the logged in user in the Users list to assign them to the group (a clean-up step takes them out again after the test).
4. Open the Group KPIs tab.
5. Enable Tickets Created if needed, select it and set Benchmark More, benchmark value 10, Time Period Current Month, Display Type Ticker (each change is saved straight away).
6. Make the Customer Service KPI call return user result 10 (equal to the benchmark), group average 8, benchmark 10.
7. Go to the Tickets page and verify the tile shows "10 / 8 / 10" and the goal IS achieved (reaching the benchmark counts).
8. Make the call return user result 9 (one below the benchmark) and reload Tickets.
9. Verify the tile shows "9 / 8 / 10" and the goal is NOT achieved.

Notes:
- The test cases are named "TaskKPI"; in the build under test the KPI feature has Claims Processing KPIs (Claims Queue ribbon) and Customer Service KPIs (Tickets ribbon), and My Tasks has no KPI ribbon. "Task" KPIs are therefore the Customer Service KPIs and "My Task" is the Tickets page.
- Shared helpers: utils/kpi.ts. After the test the user is taken out of the group again (afterEach), so the next test's ribbon only shows its own KPIs.
- The KPI service response is supplied by the test (Playwright page.route) because the setup cannot create the resolved/closed ticket history the KPI is calculated from, and a failing or forbidden service cannot be produced on demand. The KPI configuration in the UI and the ribbon rendering are real.
